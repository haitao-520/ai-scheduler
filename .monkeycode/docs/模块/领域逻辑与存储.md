# 领域逻辑与存储

本模块包含排班的领域规则与基础设施：颜色与时段判定、默认时间与命名、本地持久化、图片压缩，以及原生小部件同步桥。它不依赖任何 React 组件，可独立推理与测试。

## 结构

```
src/lib/
├── colors.ts    # 时段判定与配色
├── shift.ts     # 默认时间与班次命名
├── storage.ts   # localStorage 读写
├── image.ts     # 图片压缩
└── widget.ts    # 原生小部件同步桥
```

## 关键文件

| 文件 | 目的 |
|------|------|
| `colors.ts` | `periodForTime` 时段归类、`colorForShift` 配色、`colorFor` 名称哈希兜底 |
| `shift.ts` | `DEFAULT_TIMES` 预设、`inferTimes` 补时间、`autoShiftName` 命名、`shiftRange` 区间文案 |
| `storage.ts` | `loadShifts` / `saveShifts`、`loadSettings` / `saveSettings`、`loadChat` / `saveChat` |
| `image.ts` | `fileToCompressedDataUrl` 把图片缩放到最大 1280px 并以 JPEG 0.82 质量编码 |
| `widget.ts` | `syncCalendarWidget` 精简并发送排班快照，`getWidgetStatus` 读取诊断日志 |

## 规范

### 文件命名

- 主题名使用 camelCase，如 `colors.ts`、`shift.ts`
- 类型与逻辑同文件导出，不额外建 `types.ts`

### 代码模式

纯函数优先，输入输出明确，便于在原生端复刻：

```ts
export function periodForTime(start?: string, end?: string): ShiftPeriod | null {
  // 按与固定时段区间的重叠分钟数取最长者
}
```

存储读写统一 `try/catch`，失败时返回安全的默认值，不向上抛错：

```ts
export function loadShifts(): DayShifts {
  try {
    const raw = localStorage.getItem(SHIFTS_KEY)
    return raw ? (JSON.parse(raw) as DayShifts) : {}
  } catch {
    return {}
  }
}
```

### 错误处理

- `loadXxx` 捕获解析异常返回默认值
- `saveChat` 在写入失败时退化为保留最近 20 条且去掉旧图片
- `syncCalendarWidget` 在非原生平台直接返回，调用失败静默

### 测试

项目未配置单元测试框架。

## 添加新逻辑

1. 按主题新建或扩展现有文件，保持纯函数风格
2. 若规则需在小部件体现，在 `CalendarWidgetProvider.java` / `ShiftWidgetProvider.java` 中同步实现
3. 通过 `npm run typecheck` 验证

**检查清单**

- [ ] 函数无副作用或副作用集中在存储/网络边界
- [ ] 默认值与 `src/types.ts` 保持一致
- [ ] 与原生端算法保持一致（涉及颜色/时段时）
